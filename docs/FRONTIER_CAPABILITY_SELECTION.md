# اختيار القدرات المتقدمة وربطها بالمؤسسة

**فحص المصادر: 26 سبتمبر 2026. الحالة: ترشيح وتقييم، لا تكاملات مفعلة.**

## توجيه المؤسس

البحث يصل إلى المشاريع والنماذج والأدوات المتقدمة التي تخرج من الشركات والمختبرات العالمية، ومنها ما لا يظهر كثيرًا في قوائم الأدوات العامة. نفحص أحدث إصدار رسمي متاح ونقارن فائدته بالمهمة المطلوبة. الندرة سبب للاكتشاف، ونتيجة الاختبار سبب للاعتماد.

نجمع بين برامج مفتوحة المصدر، وأوزان نماذج ذات تراخيص منفصلة، وواجهات خدمات مرخصة عند الحاجة. تظل هوية كل نوع وشروطه واضحة. يُعاد فحص الإصدار عند التنفيذ؛ هذه القائمة ليست ادعاءً بحصر أفضل ما في العالم.

هذه الأمثلة تمثل أربعة أنواع مختلفة: موصل لمنصة مؤسسية، مشغّل تجارب، نموذج توقع متخصص، وإطار حساب علمي. دمجها يتم حول المهمة، وليس تثبيت قائمة كاملة مقدمًا.

## شروط قبول المرشح

1. **فائدة محددة:** مهمة وبيانات ومستخدم وقرار أو نتيجة قابلة للقياس.
2. **ميزة تتجاوز المحادثة المتاحة:** نقارن بأداء GPT أو Claude مع أدواتهما الحالية على نفس المهمة. إذا كفى الربط بأداة موجودة، نستخدمها.
3. **مصدر وإصدار:** مستودع أو API رسمي، تاريخ الإصدار، تغييرات جوهرية، حالة صيانة وتوافق.
4. **حق تشغيل:** نفحص ترخيص الكود والأوزان والبيانات وواجهة الخدمة كلًا على حدة.
5. **تكلفة كلية:** الاستضافة، GPU، تخزين، نقل بيانات، استدعاءات النماذج، وصيانة الربط.
6. **اختبار مقارنة:** خط أساس صالح، جودة ودقة وزمن وكلفة، مع حالات فشل وتراجع؛ لا اعتماد على عرض المورد فقط.
7. **عقد تكامل:** مدخلات ومخرجات موثقة، وإتاحة عبر MCP عند ملاءمته. الحسابات الثقيلة تبقى في خدمة مختصة، والوكيل يستدعيها ويتابع نتيجتها.

إذا أثبت مكوّن جديد تحسنًا يستحق كلفة الانتقال، يُبدّل خلف نفس واجهة القدرة. لا تحديث تلقائي للإصدارات الإنتاجية لمجرد ظهور إصدار أحدث.

## الأدوات والمساعدون المتاحون

| المورد | الدور المناسب | حالة الدليل |
|---|---|---|
| Hetzner | معالجة وخدمات ثقيلة عند فحص الموارد | الاشتراك أكده المؤسس؛ الوصول والعتاد غير مفحوصين لهذه المهمة |
| OpenRouter | تشغيل نماذج مختلفة للمهام الخلفية ومقارنة نتائجها | الاشتراك مؤكد؛ المفاتيح والحصص والنماذج المتاحة للحساب غير مفحوصة |
| Trigger.dev | المهام المجدولة وحالة التشغيل وإعادة المحاولة | الاشتراك مؤكد؛ الربط غير منفذ |
| n8n | الربط بين أنظمة المؤسسة والمراجعة | الاشتراك مؤكد؛ الربط غير منفذ |
| Cursor | تطوير الكود وتجربة تكاملات محددة | متاح حسب المؤسس؛ لم نتصل ببيئته أو نشغل مهمة عليه |
| Grok وClaude | بحث أو تنفيذ أو مراجعة مستقلة حسب المهمة | متاحان حسب المؤسس؛ لم نرسل لهما مهام أو نفترض API أو MCP صالحًا |
| أدوات أخرى | تدخل عند وجود فجوة وميزة مثبتة | لا اشتراكات أو مشتريات جديدة في خطوة التصميم |

للمهام المفوضة: وصف محدود، فرع وملفات مملوكة بوضوح، نتيجة قابلة للفحص ومراجعة قبل الدمج. لا نعد أن إجماع المساعدين دليل صحة؛ الدليل نتيجة الاختبار ومصدرها.

## كيف يحافظ الاختيار على حداثته

يضاف إلى رصد M1، بعد اعتماده وتشغيله، مسار لمتابعة الإصدارات الرسمية وتغير التراخيص والتوقف عن الصيانة. ينتج مرشحات للمراجعة تربط التطور بقدرة موجودة أو فجوة فعلية. هذا مسار مقترح؛ لم تُنشأ له جدولة أو أتمتة الآن.

تُسجل لكل ترقية أربعة تواريخ: إصدار المورد، تاريخ فحصنا، تاريخ الاختبار، وتاريخ الاعتماد. تظهر للزائر فقط القدرات التي نجحت وشغّلت بالفعل؛ تبقى المرشحات داخل سجل التطوير.
