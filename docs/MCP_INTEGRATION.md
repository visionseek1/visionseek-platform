# التكامل مع MCP — مبدأ أساسي لبناء القدرات

**26 سبتمبر 2026 · توجيه المؤسس · تصميم مقترح، بلا تنفيذ أو اتصال مثبت حتى الآن.**

## القرار

تستفيد VisionSeek من قوة النماذج التي يستخدمها صاحب المؤسسة بالفعل. نتيح قدراتنا وبياناتنا وأعمالنا المستمرة عبر MCP، ونربط الأدوات الخارجية المناسبة عبر MCP عند توفر موصل موثوق. يبقى الموقع مكانًا لمراجعة الحالة والأدلة والنتائج والصلاحيات واعتماد التنفيذ.

**فلتر أي ميزة جديدة:** هل تحقق نتيجة تتجاوز ما تستطيع المحادثة المباشرة إنجازه بالفعل مع الملفات والأدوات المتاحة للمستخدم؟ إذا كانت القيمة مجرد تلخيص أو بحث عام أو صياغة، نستخدم النموذج أو موصله الموجود. الاستثمار في البناء يذهب إلى بيانات متصلة مستمرة، سياق مؤسسي محفوظ، تنفيذ متكرر موثوق، حسابات واختبارات متخصصة، أو تعاون وصلاحيات وأدلة يمكن الرجوع إليها.

المحادثة نفسها قد تدعم الذاكرة والأتمتة والموصلات. لذلك المقارنة تكون مع قدراتها الفعلية وقت الاختيار، ثم نثبت الفجوة التي يضيفها مكوّن VisionSeek. وجود MCP ليس ميزة تنافسية بمفرده؛ جودة التكامل والنتائج التشغيلية هما معيار القبول.

## اتجاهات الاتصال

| المسار | الدور | مثال مقترح |
|---|---|---|
| ChatGPT / Claude أو عميل متوافق ← VisionSeek MCP | نتيح أدواتنا وسياق المؤسسة للمساعد الذي يفضله المستخدم | استرجع أدلة برنامج محدد، افحص حداثة مصادره، واعرض نتيجة آخر اختبار |
| مشغّل VisionSeek → خوادم MCP خارجية معتمدة | نستخدم أداة أو بيانات جاهزة بصلاحية المستخدم بدل إعادة بنائها | اقرأ مستندًا مسموحًا به من نظام المؤسسة أو أنشئ مهمة مخولة في أداتها الحالية |
| مشغّل VisionSeek → API / SDK مباشر | تكامل مناسب عندما لا يتوفر MCP موثوق أو عندما يحتاج العمل نقل بيانات بكميات كبيرة | جمع دفعات بحث مجدولة أو رفع ملف ومعالجته |

MCP يربط التطبيقات بالأدوات والبيانات؛ التطبيق المضيف هو الذي يدير النموذج ويختار الأدوات. OpenRouter يظل طبقة تشغيل نماذج للمهام الخلفية أو وظائف الموقع التي تحتاجها. استعمال VisionSeek من محادثة خارجية لا يستلزم استدعاء نموذج ثانٍ لكل خطوة.

## البنية المقترحة

1. **واجهة استخدام مشتركة للقدرات:** خدمات داخل التطبيق لها مدخلات ومخرجات محددة؛ تستدعيها واجهة الموقع وأدوات MCP بنفس قواعد الصلاحيات والتسجيل.
2. **VisionSeek MCP server:** نقطة اتصال بعيدة تحت الاستضافة الحالية، مسار مرشح `/api/mcp` بعد فحص توافق SDK وVercel. لا DNS جديد، ولا فتح منفذ عام على Hetzner في هذه الخطوة.
3. **بيانات وسجل تنفيذ دائم:** Supabase يحفظ هوية المؤسسة والأدلة والموافقات وحالة التشغيل. لا نعتمد على ذاكرة المحادثة أو اتصال MCP لحفظ حالة المشروع.
4. **مهام طويلة:** Trigger.dev يدير التشغيل، وخدمات Hetzner تنفذ المعالجة الثقيلة عند الحاجة. أداة MCP ترجع `run_id` ورابط النتيجة؛ أداة حالة تستعلم عن التقدم. لا نفترض أن كل عميل يدعم نفس آلية المهام الطويلة.
5. **تكامل خارجي:** n8n أو عميل MCP في المشغّل، حسب الوظيفة. سجل موصلات معتمد يحدد الخادم والأدوات المسموحة والمستخدم ونطاق البيانات وإصدار الأداة.

## عقد البداية المقترح

أسماء الأدوات أدناه تصميم قابل للتعديل، وليست endpoints موجودة.

| المرحلة | الأدوات المقترحة | النتيجة المسموح بها |
|---|---|---|
| M0 — قراءة | `sources_status`, `evidence_search`, `evidence_get` | بيانات من أول مصدر متصل، تاريخها وأدلتها ونطاق صلاحية طالبها |
| M1/M3 — تحليل محفوظ | `scan_start`, `run_get`, `institution_context_get` | تشغيل محدود مخول، متابعة حالته وقراءة سياق المؤسسة من سجلات فعلية |
| M4 — إعداد اختبار | `program_get`, `experiment_propose` | مسودة برنامج أو تجربة، موارد وقيود وتوقعات واضحة؛ لا تُعد النتيجة موافقة بشرية |
| مرحلة تشغيل معتمدة | `experiment_run`, `result_get` | تنفيذ تجربة مأذون بها، ثم نتيجة قابلة للإعادة لها أدلة وإصدارات |

تُرجع الأدوات مخرجات منظمة: المعرّفات، الحالة، مصدر كل معلومة، وقت الحدث والجلب، القيود والأخطاء. تُوثق مخططات المدخلات والمخرجات وتُحدد حدود حجم النتائج والترقيم. موارد MCP تعرض السياق عند دعم العميل لها؛ أدوات القراءة تعطي طريقًا بديلًا للعملاء الذين يعتمدون الأدوات فقط. Prompts اختيارية لتوجيه مهمة، ولا تقوم مقام القدرة.

## الصلاحيات والآثار الخارجية

- تحقق الخادم من هوية المستخدم والمؤسسة والنطاق في كل طلب؛ لا يثق في `institution_id` يكتبه النموذج وحده.
- OAuth مناسب للاتصال البعيد، مع صلاحيات محددة قابلة للإلغاء وفصل القراءة عن التنفيذ. يُتحقق من جمهور الرمز؛ لا تمرير رموز العملاء كما هي إلى خدمات أخرى.
- ما يقرأه النموذج من مستند أو نتيجة أداة بيانات غير موثوقة، ولا يمنحه صلاحية تشغيل إضافية.
- الأثر الخارجي يحتاج تفويضًا صالحًا محددًا. عند الحاجة لموافقة بشرية، يثبتها مستخدم مخول عبر شاشة مراجعة أو تدفق هوية مستقل؛ لا يملك الوكيل اعتماد طلبه بنفسه بأداة أخرى.
- سجلات التشغيل تربط المستخدم والعميل والأداة والوسائط المصرح بها والنتيجة والتكلفة. لا أسرار في النتائج أو الروابط أو السجلات.
- قبل تشغيل مهمة مكلفة تُراجع حدود الموارد والميزانية والتكرار؛ مفاتيح منع التكرار تحمي من إعادة تنفيذ الأثر عند إعادة المحاولة.

## اختبار القبول

1. أول قراءة تعمل من صفحة الموقع ومن عميل MCP حقيقي وتعيد نفس السجلات والأدلة.
2. نسجل توافق كل عميل وإصدار البروتوكول عمليًا؛ لا ندعي اتصال ChatGPT أو Claude لمجرد دعم المعيار في التوثيق.
3. المستخدم غير المخول لا يرى بيانات مؤسسة أخرى، حتى مع تعديل معرّفات الطلب. إلغاء الصلاحية يمنع الطلب اللاحق.
4. سؤال بلا دليل يرجع نقص الدليل؛ لا ينتج نتيجة مختلقة.
5. إعادة طلب تشغيل لا تكرر الأثر. تستمر المهمة وحالتها خارج عمر المحادثة.
6. نقارن مهمة واحدة بمحادثة مباشرة مجهزة بنفس البيانات والأدوات المتاحة؛ نسجل الوقت والكلفة وجودة الأدلة والعمل اليدوي وقابلية الإعادة. لا نوسع الميزة قبل إثبات إضافة مفيدة.

## نتائج فحص التوافق الحالية

- فحص المستودع لم يجد اعتماد MCP أو تكامل OpenRouter قائمًا في ملفات التطبيق التي فُحصت.
- [توثيق OpenAI](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt) يشرح التطبيقات البعيدة والتفعيل والصلاحيات حسب خطة مساحة العمل. أهلية الحساب الحالي لم تُفحص؛ لا نعد بإتاحة كل العمليات فيه.
- [توثيق Claude](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) يشرح الموصل البعيد وOAuth. الاتصال البعيد يصدر من بنية Anthropic ويتطلب الوصول إلى الخادم؛ لم نجرب ربط الحساب الحالي.
- [المواصفة](https://modelcontextprotocol.io/specification/2026-07-28/changelog) غيرت سلوك النقل في هذا الإصدار؛ نختبر التوافق بدل افتراضه. [TypeScript SDK الرسمي](https://github.com/modelcontextprotocol/typescript-sdk) يعرض v2 كمسار مستقر وv1 كمسار صيانة؛ نثبت إصدارًا مدعومًا بحسب مصفوفة العملاء والبيئة عند البناء.
- [تفويض MCP](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) و[إرشادات الأمان](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/tutorials/security/security_best_practices.mdx) هما مرجع الضوابط.

هذا التوجيه يدخل في تصميم M0: أول اتصال حقيقي للقراءة عبر MCP يصبح جزءًا مقترحًا من قبوله. ما زالت موافقة الخطوة 0 مطلوبة وفق ملف التكليف قبل إنشاء كود الغرفة أو اتصالها.
